Lời mở đầu

Vì sao một model đã train xong vẫn chưa phải là production service?

Một model đã được train xong chưa phải là một production service.

Trong môi trường nghiên cứu, ta thường quan tâm nhiều đến accuracy, loss curve, training throughput, checkpoint tốt nhất, hoặc cách cải thiện architecture. Nhưng khi model bước vào production, câu hỏi thay đổi hoàn toàn:

  • Model có trả lời đủ nhanh không?
  • p95 và p99 latency có ổn định không?
  • GPU có được sử dụng hiệu quả không?
  • Có thể phục vụ nhiều request đồng thời không?
  • Có thể rollout model mới mà không làm hỏng hệ thống không?
  • Khi chất lượng giảm, latency tăng, GPU OOM, hoặc traffic spike thì debug thế nào?
  • Chi phí phục vụ mỗi request hoặc mỗi token là bao nhiêu?

Chuỗi bài học này được xây dựng để trả lời các câu hỏi đó một cách có hệ thống.

Hành trình xuyên suốt 10 lesson:

trained model artifact
  -> portable graph representation
  -> optimized runtime execution
  -> hardware-aware compilation
  -> quantized model execution
  -> inference serving platform
  -> benchmarking and profiling

Nói ngắn gọn, đây là chuỗi bài về AI Optimization cho inference systems: tối ưu model, runtime, GPU execution, serving layer, observability, rollout strategy và chi phí vận hành.

AI Optimization nghĩa là gì?

Quan trọngÝ chính

“Optimization” không chỉ là làm model chạy nhanh hơn. Trong chuỗi bài này, nó gồm model, runtime, hardware, serving, hệ thống (p99/cost) và vận hành (rollout/monitoring).

Trong nhiều tài liệu, “optimization” thường bị hiểu hẹp là làm model chạy nhanh hơn. Ở đây khái niệm đó được mở rộng thành nhiều tầng:

Tầng Nội dung
Model-level Graph, operator, tensor shape, precision, quantization, memory footprint
Runtime-level Execution backend, overhead, data movement, CUDA / TensorRT / ONNX Runtime
Hardware-level GPU execution, Tensor Cores, memory bandwidth, batching, streams, kernel
Serving-level Dynamic batching, concurrent execution, model instances, scheduler
System-level Latency–throughput trade-off, p99, autoscaling, capacity, cost/request
Operational Rollout an toàn, monitoring, alerting, rollback, incident response

Trọng tâm không phải một thư viện riêng lẻ, mà là tư duy hệ thống khi đưa AI model vào production.

Tư duy xuyên suốt

Một trained model thường chỉ là một artifact: file .pt, .onnx, .engine, checkpoint, hoặc model directory. Production inference system là một đường đi đầy đủ:

client request
  -> preprocessing
  -> request queue
  -> batching scheduler
  -> runtime execution
  -> GPU kernels
  -> postprocessing
  -> response
  -> metrics / logs / traces

Mỗi bước đều có thể trở thành bottleneck.

Một model nhanh trên notebook không chắc nhanh trong service. Một engine nhanh trong trtexec không chắc nhanh sau HTTP gateway. Average latency thấp vẫn có thể fail production nếu p99 quá cao. Deployment “thành công” vẫn thất bại nếu quality regression không được phát hiện sớm.

Cảnh báoNguyên tắc xuyên suốt

Không tối ưu bằng cảm giác. Hãy đo, phân tích, tối ưu, benchmark lại, rồi mới productionize.

Bạn sẽ học được gì?

Sau khi hoàn thành 10 lesson, bạn nên có khả năng:

  • Giải thích vai trò của ONNX như intermediate representation cho model graph
  • Export, inspect, validate và debug ONNX model
  • Chạy model bằng ONNX Runtime với nhiều Execution Providers
  • Hiểu TensorRT build engine, tactics, optimization profiles, FP16/INT8
  • Hiểu quantization như workflow (scale, calibration, Q/DQ, accuracy recovery) — không chỉ “bật INT8”
  • Deploy bằng NVIDIA Triton Inference Server
  • Cấu hình dynamic batching, model instances, versioning và metrics
  • Benchmark bằng trtexec, Perf Analyzer, Model Analyzer và Nsight Systems
  • Phân tích p50/p95/p99, throughput, GPU utilization, queue time và bottleneck
  • Thiết kế canary, A/B, shadow traffic, rollback và incident response
  • Hiểu khác biệt classic inference vs LLM inference (KV cache, continuous batching, PagedAttention, vLLM, TensorRT-LLM, token metrics)
  • Xây capstone end-to-end: PyTorch → ONNX → TensorRT → Triton → benchmark → monitoring → production readiness

Dành cho ai?

Phù hợp với:

  • Machine Learning Engineer muốn đi sâu model deployment
  • MLOps Engineer muốn hiểu inference optimization, không chỉ deploy container
  • Backend Engineer xây AI service và cần hiểu GPU/runtime/serving
  • Data Scientist chuyển từ notebook sang production-grade inference
  • AI Infrastructure Engineer cần roadmap có hệ thống về ONNX, TensorRT, Triton và LLM serving

Không yêu cầu chuyên gia CUDA từ đầu. Nên quen Python, PyTorch, command line và khái niệm deep learning cơ bản.

MẹoĐào sâu: mục tiêu từng giai đoạn

Giai đoạn 1 — Lesson 1–3: hiểu inference từ góc nhìn system (tensor, graph, runtime, backend, data movement). Kỳ vọng: export PyTorch→ONNX, inspect graph, ORT baseline, hiểu CPU / CUDA EP / TensorRT EP khác nhau thế nào.

Giai đoạn 2 — Lesson 4–5: vì sao TensorRT nhanh hơn runtime thông thường; quantization giảm memory/compute nhưng có thể giảm accuracy. Kỳ vọng: build engine từ ONNX, trtexec, optimization profiles, FP16 vs INT8, hướng xử lý khi INT8 làm accuracy giảm.

Giai đoạn 3 — Lesson 6–8: từ artifact thành service có metrics, batching, versioning, rollout. Kỳ vọng: Triton repository, serve ONNX/TRT, Perf Analyzer, latency breakdown, canary + rollback, checklist production readiness.

Giai đoạn 4 — Lesson 9–10: LLM serving khác classic inference; tổng hợp thành project. Kỳ vọng: prefill vs decode, KV cache memory, continuous batching / PagedAttention, TTFT / ITL / tokens/s / goodput, capstone end-to-end.

Sản phẩm cuối khóa

Portfolio tối thiểu:

Model: ResNet-50 or similar vision model
Export: PyTorch -> ONNX
Validation: PyTorch vs ONNX Runtime numerical comparison
Optimization: ONNX -> TensorRT FP16 engine
Serving: Triton Inference Server
Benchmark: trtexec + Perf Analyzer
Monitoring: Prometheus metrics
Operations: canary rollout + rollback plan + incident runbook
Report: latency, throughput, GPU utilization, trade-offs, production readiness

Mở rộng LLM (tuỳ chọn):

Model: small open-source LLM
Serving: vLLM or TensorRT-LLM
Metrics: TTFT, TPOT, tokens/s, request concurrency
Optimization: prefix caching, quantization, batching strategy
Report: cost per 1M tokens and capacity planning

Sáu nguyên tắc thực chiến

  1. Baseline trước, tối ưu sau — không bật TensorRT/FP16/INT8/batching/cache trước khi có baseline.
  2. Đo cả latency và throughput — throughput cao nhưng p99 xấu có thể không hợp real-time; ngược lại latency thấp nhưng throughput thấp có thể quá đắt.
  3. Tách model latency khỏi end-to-end — gateway, preprocess, serialize, queue, copy, postprocess đều tính.
  4. Dynamic shape là quyết định thiết kế — linh hoạt hơn nhưng optimization khó hơn; TensorRT cần optimization profiles.
  5. Quantization là thay đổi numerical — cần accuracy validation, calibration data và rollback plan.
  6. Production rollout là một phần của optimization — model nhanh hơn nhưng không rollout an toàn thì chưa phải improvement.

Kết luận

AI Optimization không chỉ nằm ở model. Nó nằm ở toàn bộ đường đi từ model artifact đến production inference service.

ONNX chuẩn hóa graph. ONNX Runtime thực thi trên nhiều backend. TensorRT compile/tối ưu cho NVIDIA GPU. Quantization giảm compute và memory. Triton serve ở production scale. Profiling đo đúng bottleneck. Rollout/monitoring vận hành an toàn. vLLM và TensorRT-LLM mở rộng sang LLM serving.

Nếu nắm được chuỗi này, bạn không chỉ “deploy model”, mà có thể thiết kế, tối ưu, benchmark và vận hành một AI inference system thực tế.
